# Inbound AI receptionist setup

## What this repository supports

The production web API is the NestJS service in `server/`, and it owns the current tenant appointment records in SQLite. There is no CareStack integration or provider schedule/availability API in this repository. The voice tools below use the existing clinic calendar; they can identify an exact duplicate doctor/date/time and create a confirmed record. They cannot verify a provider's external schedule, patient identity, or CareStack status. Cancellation and rescheduling deliberately hand off to staff.

The Python service is a separate demo agent with in-memory data. Inbound voice actions do not use it.

## Provider setup

Set a random `VOICE_TOOL_SECRET` of at least 32 characters on the Nest server and restart it. After saving a clinic's calling settings, copy that clinic's derived `voice_tool_secret` from Super Admin into the provider's tool configuration. Prefer `x-voice-tool-secret` or `Authorization: Bearer <clinic-specific-secret>` as a constant HTTP header. If the Exotel account does not expose a header value, use a POST body parameter named `tool_secret` with a **Constant Value** in the attached tool configuration; never map it from an LLM prompt. The API validates the same tenant-bound credential and strips the body parameter before dispatch. Do not use the master `VOICE_TOOL_SECRET` as the clinic credential, or put any credential in a URL/query string. Both providers call `POST https://<public-api-host>/api/voice/tools/<tenant-id>` with a JSON body. Supported actions are `clinic_info`, `faq`, `availability`, and `book`; `cancel` and `reschedule` return an unsupported response.

Clinic administrators maintain the AI receptionist's approved reference in the Agents page: clinic address, services, doctors, fees, supported languages, custom receptionist instructions, and up to 25 FAQs. `clinic_info` returns this context at call start; `faq` returns an approved answer or explicitly asks the agent to hand off. This is live context retrieval and prompt grounding, not model fine-tuning. Changes apply to subsequent tool calls.

### Sarvam Voice Agents

1. Create a Hindi/Hinglish Sarvam Voice Agent and configure it to identify itself as AI, answer only returned clinic data, repeat appointment details and get explicit confirmation before booking. Add the API tool endpoint and the clinic-specific secret above.
2. In Sarvam Deploy → Phone Numbers, add the Exotel Account SID, API key, token and regional base URL. Create an Exotel app with Voicebot applet URL `https://apps.sarvam.ai/api/app-runtime/channels/exotel`, then assign it to the clinic's Exophone.
3. Set `SARVAM_API_KEY` on the Nest server. In Super Admin → Configure calling, select Sarvam and save the Exophone, Sarvam organization, workspace, agent ID/version and Exotel connection ID.
4. Configure and test the agent's tools with a non-production tenant. **Activate inbound calls** sends Sarvam's deployment API request and immediately creates an active deployment; it may incur usage charges. The app sends the configured open/close hours and timezone, using all seven days because clinic open days are not modeled. Configure Exotel's fallback flow for out-of-hours calls. The app currently cannot pause/delete a remote deployment.

### Exotel Voicebot

1. In Super Admin → Configure calling, enter the clinic's Account SID, API Key, API Token, ExoPhone, region, and App/Flow ID. API Key and API Token are encrypted in the server database and never returned to the browser. Existing deployments may continue using the legacy `EXOTEL_API_KEY` and `EXOTEL_API_TOKEN` environment variables.
2. Set a stable `CREDENTIALS_ENCRYPTION_KEY` of at least 32 characters on the Nest server. Back it up securely and keep it unchanged so saved provider credentials can be decrypted after restarts and restores.
3. Click **Verify Exotel account**. This calls Exotel's read-only Account Balance API; it does not dial or place a call.
4. Save calling settings. Super Admin then shows this clinic's public API tool endpoint and clinic-specific `x-voice-tool-secret`. `VOICE_TOOL_SECRET` (at least 32 random characters) must be set on the API server. The API must have a public HTTPS URL that Exotel can reach; localhost is not reachable from Exotel.
5. In Exotel Voicebot → Build Bot → Tool Integration, add active POST integrations to the endpoint shown in Super Admin. Prefer a constant `x-voice-tool-secret` header, or `Authorization: Bearer <clinic-specific-secret>`. If the account UI has no header value field, add a POST body parameter named `tool_secret` and set it to a **Constant Value** in the attached tool's parameter mapping; do not expose it to the LLM prompt. Never use the master `VOICE_TOOL_SECRET` or put a credential in the URL/query string. For every tool call, `action` must be a POST JSON body parameter at the top level, not only a tool name, URL parameter, header, or nested `arguments` object. Configure these actions as constants: `clinic_info`, `availability`, and `book`; map the other fields from caller/tool arguments. FAQ is not needed for this setup. Example clinic-info body: `{"action":"clinic_info"}`. Availability must include `date`, `time`, and `doctor_name` (use the empty string for no doctor preference); booking must include all required fields and `confirmed: true` only after the caller confirms. Attach each tool to the bot and publish it.
6. In App Bazaar, create a call flow with a Greeting and IVR Menu. For example, say “Press 1 for appointment booking”; route digit 1 to this clinic's published Voicebot applet. Assign the flow to the clinic's ExoPhone. Test through the Voicebot console or call the ExoPhone.

7. To copy Exotel call details into CareStack, configure the Voicebot's `transcript_events` webhook to `https://<public-api-host>/api/exotel/voicebot/webhooks/<tenant-id>`. The webhook stores the Exotel call SID, caller number, timestamps, and transcript in CareStack. Exotel documents `custom_parameters` in the Voicebot webhook payload: pass the tenant-specific `voice_tool_secret` from Super Admin as `custom_parameters.carestack_webhook_token` in the call/session configuration. Keep it out of prompts and tool arguments; CareStack validates it and does not log or return it. If your Voicebot setup cannot pass custom parameters, the endpoint also accepts HTTP Basic Auth using `EXOTEL_VOICEBOT_WEBHOOK_USERNAME` and `EXOTEL_VOICEBOT_WEBHOOK_PASSWORD`; ask Exotel Support to configure those credentials for Voicebot webhook delivery. The username must be at least 16 characters and password at least 32 characters. The Voicebot webhook guide does not specify custom HTTP headers or built-in webhook authentication. Calls without a valid body token or configured Basic Auth, or from a different configured Voicebot ID, are rejected.

The CareStack tenant admin can sync existing Inbox calls using `POST /api/tenants/<tenant-id>/exotel/calls/sync` with `{"start_date":"2026-10-01","end_date":"2026-10-15"}` and their CareStack bearer token. Exotel limits this API to six months of history and date ranges of at most 31 days; the response returns `next_after` if more pages remain. `GET /api/tenants/<tenant-id>/exotel/calls` returns the synced calls. `GET /api/tenants/<tenant-id>/exotel/calls/<call-sid>/recording` looks up the call through Exotel's authenticated Call Details API and returns its recording URL when one exists. Recording must be enabled in the Exotel call flow/account. The URL can be short-lived when Exotel Secure Recordings is enabled; treat it as sensitive. Call data and transcripts are retained in the CareStack tenant's application state, with the most recent 100 calls and up to 100 transcript segments per call. Exotel's [Bulk Call Details API](https://developer.exotel.com/api/call-details-bulk) provides call metadata and recording links, not Voicebot conversation transcripts; transcripts for new Voicebot calls arrive through the transcript webhook. Exotel's [ExoVoiceAnalyze API](https://developer.exotel.com/api/exovoiceanalyze) can generate transcripts from recordings, but it is asynchronous, chargeable, and account-enabled by request, so CareStack does not trigger it automatically.

To create a booking from a reviewed call, the tenant admin can call `POST /api/tenants/<tenant-id>/exotel/calls/<call-sid>/book` with the booking JSON below. The caller number must match Exotel's caller ID, and `confirmed` must be `true`; the API validates the future slot, clinic schedule, and conflicts, then persists the booking and returns its ID. This is a staff-reviewed API action. The normal live Voicebot booking should continue to call the `book` tool during the call after reading back the appointment and obtaining the patient's explicit confirmation.

The IVR selection routes the caller to the booking agent; a digit alone is not enough to create an appointment. The bot collects the patient's name, callback number, date/time and reason, and asks for a doctor preference only if the caller has one. Date expressions such as “today”, “tomorrow”, “aaj”, and “kal” are normalized using the clinic timezone; dates without a year use the current clinic-local year. If no doctor is requested, `availability` selects a free doctor from the clinic's configured doctor list (or doctors already present in its appointment records). The bot must tell the caller which doctor was selected and get confirmation of the complete booking details before calling `book` with that doctor name. The API persists the confirmed booking and returns its ID for the bot to read back. Exotel's setup supports an IVR menu before the Voicebot applet; see [Exotel Voicebot guide](https://docs.exotel.com/intelligent-voice-agents) and [Voicebot tool integration](https://docs.exotel.com/intelligent-voice-agents/tool-integration-for-voicebot).

Exotel Voicebot supplies its own WebSocket endpoint. This application does not run a separate AgentStream WSS server. Exotel's lower-level AgentStream API is a different option that requires a public WSS bot and is not selected by this integration.

## API tool contract

All requests require the clinic-specific credential, supplied as `x-voice-tool-secret`, `Authorization: Bearer <secret>`, or (for Exotel configurations without a header value field) a constant POST body field named `tool_secret`. Invalid/missing credentials return 401. Body credentials are validated against the URL tenant and removed before action dispatch; the server does not log or return them. Never use a caller/LLM-provided credential or put one in the URL/query. Example bodies (add `tool_secret` only when using the body fallback):

```json
{"action":"clinic_info"}
{"action":"faq","question":"Do you provide dental care?"}
{"action":"availability","date":"tomorrow","time":"11 AM"}
{"action":"book","request_id":"unique-call-request-123","confirmed":true,"patient_name":"Example Patient","phone_number":"+919876543210","doctor_name":"Dr. Example","date":"2030-04-10","time":"11:00","reason":"Consultation"}
```

`date` accepts ISO dates, common day/month dates, month names with an optional year, and today/tomorrow expressions in English or Hindi/Hinglish. An omitted year means the current year in the clinic timezone. `time` accepts 24-hour time and common spoken numeric forms such as `11 AM` or `10 baje`; unclear values should be clarified by the bot. Availability requires a string `doctor_name`; an empty string tells the API to check all configured/known clinic doctors and return actual available names. The bot should repeat the selected doctor and get the caller's approval. If `doctor_name` is omitted from `book`, the API does not create an appointment; it returns `confirmation_required` with a suggested doctor. The bot must tell the caller, get confirmation, and call `book` again with that `doctor_name`. If no doctor list or prior doctor records exist, the API asks the clinic to configure doctors rather than inventing a provider. Booking requests need an idempotency key; retries return the prior booking. `confirmed: true` is required for persistence. Each clinic configures an appointment length (15, 20, 30, 45, or 60 minutes; default 30). Availability and booking check the entire requested interval against every non-cancelled, non-no-show appointment for the same doctor. Exact duplicates and partial overlaps are rejected; back-to-back appointments are allowed. New bookings store their duration; older bookings use the clinic's current configured length. This checks the clinic's local calendar only, not an external CareStack/provider schedule. This endpoint does not search for patients or reveal existing patient records.

### Exotel availability tool argument schema

The live `CarestackCheckAvailabilitySchema` is configured in Exotel and is not generated from this repository. The current validation error confirms Exotel requires `action`, `date`, `time`, and `doctor_name`; the agent must send all four on every call. A canonical JSON Schema copy is in `server/schemas/exotel-carestack-check-availability.schema.json`; update the Exotel tool and its attached parameter mappings to match it. `doctor_name` remains a required string at the tool boundary; pass `""` when the caller has no preference, which means check all real doctors. The CareStack API resolves relative dates using the clinic's current timezone at request time (default `Asia/Kolkata`), normalizes spoken times, and checks only doctor names configured in clinic data or present in actual appointment records. It rejects unknown doctor names and does not invent doctors or return mock availability. For “aaj 12 baje”, pass `date: "aaj"`, `time: "12:00"`, and `doctor_name: ""`; for “kal shaam 5 baje”, pass `date: "kal"`, `time: "17:00"`, and `doctor_name: ""`.

```json
{
  "type": "object",
  "properties": {
    "action": { "type": "string", "const": "availability" },
    "date": { "type": "string", "description": "Required. Preserve relative dates like aaj/today or kal/tomorrow; backend resolves them at call time in clinic timezone. Explicit dates use YYYY-MM-DD." },
    "time": { "type": "string", "description": "Required. Normalize spoken time to HH:mm, e.g. 12 baje => 12:00; shaam 5 baje => 17:00." },
    "doctor_name": { "type": "string", "description": "Required. Exact doctor name from clinic_info.doctors, or empty string to check all configured doctors if caller has no preference. Never guess." }
  },
  "required": ["action", "date", "time", "doctor_name"],
  "additionalProperties": false
}
```

Set `action` to the constant `availability`; map `date`, `time`, and `doctor_name` from the conversation and verify that the attached tool mapping includes all three. Do not attach a schema with `date` or `doctor_name` omitted. This is an Exotel console configuration change: changing CareStack code does not automatically update an already registered Exotel tool schema. The API accepts an empty `doctor_name` and checks all real configured/known doctors; the registered schema still requires the field to be present.

## Pricing and trial

Sarvam's currently published India Voice Agents pay-as-you-go rate is ₹3.50/minute, with no monthly fee under 3,000 minutes/month; calls round up to a full minute and prices exclude GST. Exotel still bills its own usage and number rental. Exotel's pricing page currently advertises a 7-day trial with 500 credits, while its trial-account docs describe a 15-day/₹1,000 trial for some accounts. These published terms differ, so verify the credit amount and number rental in the actual Exotel dashboard before testing. Trial credits cover Exotel usage only; Sarvam agent minutes are separate. See [Sarvam pricing](https://docs.sarvam.ai/voice-agents/pricing), [Exotel pricing](https://exotel.com/pricing/business-phone-system/), and [Exotel trial account details](https://docs.exotel.com/business-phone-system/create-a-trial-account?hl=en-IN).

Sarvam's Exotel instructions require a Sarvam phone-number connection, an Exotel Voicebot applet pointing at Sarvam's hosted endpoint, the Exophone assignment, and an inbound deployment. The hosted endpoint provides the audio WebSocket. Exotel's API account check uses its documented `GET /v1/Accounts/{account_sid}/Balance.json` endpoint with HTTP Basic authentication. See [Sarvam Exotel setup](https://docs.sarvam.ai/voice-agents/deploy/telephony/exotel), [Sarvam create deployment API](https://docs.sarvam.ai/voice-agents/api/deployments/create), [Exotel Voicebot guide](https://docs.exotel.com/intelligent-voice-agents), and [Exotel programmable voice API](https://developer.exotel.com/docs/voice).

## Current limitations

- No CareStack client or credentials exist in this codebase. Clinic calendar records are local SQLite state.
- Clinic context and FAQs are saved per clinic and returned to the agent as approved reference. The tool does not validate those facts; clinic staff must keep them accurate. The agent must hand off unsupported questions.
- Patient identity verification, patient search, rescheduling, cancellation, and human call transfer are not implemented. Exotel call-history/transcript ingestion requires the webhook and Basic Auth setup above. Sarvam documents Exotel transfer as requiring enablement by Sarvam support.
- Sarvam deployment creation is live and may be billable. Saving settings does not create one. Exotel Voicebot creation/publication is manual in its console. No external deployment or real telephone call was made during implementation.
